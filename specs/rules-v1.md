# Proposed gameplay rules v1

Status: v1 Modern/Fusion mechanics implemented in M2; human handling/balance validation remains pending. Built-in C++ presets, not a runtime JSON loader, are used; see `docs/M2_VALIDATION.md` for codec and rules-identity differences. Classic remains gated by `classic-reference.md`. M0 executable implements only `core-api-v1.md` diagnostic behavior. Changing any normative value requires a new rules version and compatibility review.

## Data and coordinates

`rules/schema-v1.json` validates the restricted Modern/Fusion preset manifest; `rules/modern-v1.json` is a proposed example, not loaded by M0. Named table IDs refer to exact tables in these specs, not external standards. JSON validation is only the structural layer; a future loader must additionally reject non-matching preset constants and unsupported table IDs. Classic is intentionally not admitted by this schema while its constants are unknown.

Board x=0..9, y=-20..19, y increasing downward. Cells outside storage collide. Row-major board storage starts at y=-20; 0 empty, I/J/L/O/S/T/Z=1..7, garbage=8. Visible rows y=0..19. Piece local geometry and kicks are in `rotation-v1.md`; spawn origin (3,-2), orientation 0 for every piece. Collision means any occupied cell at an occupied/outside board position. Spawn collision loses. After clear, a lock whose surviving piece cells are all y<0 loses; if no piece cells survive clearing, it survives. Garbage overflow loses before spawn. No ceiling grace outside storage.

Modern: clock 60/1 ticks/s; preview 5; hold once per active piece; hard drop enabled; ghost enabled. Fusion: same clock, preview 1, hold/hard drop disabled, ghost off by default. Fusion Classic-like cadence is explicitly a placeholder: proposed DAS 16 ticks / repeat 6 pending Classic measurements and playtest. It is not an authenticity claim. Modern DAS 6 / repeat 2 ticks (100 / 33.333... ms); lock delay 30, reset cap 15. Fusion lock delay 18, cap 8. Both use entry delay 0 and clear delay 0. Spawn happens at end of the locking tick; no input applies to the new piece until next tick. No buffering hold/rotation across spawn.

## Tick order and movement

Ticks start at 0; state is the pre-tick state. Incorporate scheduled external events; resolve input; hold; rotation; horizontal; hard drop or vertical/lock; classify/merge/clear/reward/cancel/dispatch; spawn boundary garbage and spawn; increment tick. Resolve all players before dispatching new attacks to recipients at tick+1. Battle ordering is in `battle-v1.md`.

Logical held bits: left/right/down/CW/CCW/hold/hard-drop/target-next = bits 0..7. At gameplay boundaries derive pressed=held & ~previous-held and released=previous-held & ~held. Core diagnostic has a separate small mask, specified in its API. Opposite horizontal directions: last pressed wins; presses simultaneous this tick tie neutral until a new directional press or one is released; releasing one selects the other held direction. Direction selection change causes an immediate attempted cell move and resets charge. Continue held direction: first repeat at delay ticks since selection, then every repeat ticks. Wall failure still charges and consumes repeat attempts. Neutral clears charge. CW and CCW simultaneous presses cancel; rotation, hold and hard drop act on rising edges only. Soft drop acts while held. Successful hold resets orientation/origin/gravity/lock and last-rotation marker, and ends piece actions this tick. Empty hold consumes next piece; occupied hold swaps; hold becomes available after the next lock. Check hold spawn collision immediately.

Gravity is a project choice: level=min(20, floor(total-cleared-lines/10)); interval ticks by level 0..20 is [60,48,40,32,26,20,16,12,10,8,6,5,4,3,2,1,1,1,1,1,1]. Increment gravity accumulator each active tick; while >= interval subtract interval and attempt down one cell, stopping after first blocked attempt (discard remaining accumulator on blockage). Soft drop uses interval=min(gravity interval,2), not additive gravity. Successful soft-drop cells score 1; successful hard-drop cells score 2. Hard drop moves to the last valid row, preserves rotation marker, and immediately locks; no normal gravity/lock processing afterward.

After non-hard-drop actions, evaluate grounded via a downward collision probe. First grounded tick sets lock elapsed=1. A successful lateral/rotation action while already grounded resets elapsed=0 if reset count<cap, increments count, then that tick's grounded evaluation adds 1. If ungrounded set elapsed=0; reset count persists for this piece. Failed actions do not reset. Lock when elapsed>=delay; new pieces initialize timers/counts to zero. Hold initializes timers independently. No 180-degree rotation. Successful lateral movement clears last-rotation; successful rotation sets it; failed actions and vertical movement preserve it.

Clear all full rows simultaneously; collapse surviving rows downward, insert empty rows at top. Score and attack per `battle-v1.md`. Score and lines are u64 saturating; timers and tick are u64 with overflow returned as an error before mutation. Other counters have stated bounds; never rely on signed overflow.

## Randomization and identity

Project PRNG: xorshift32, unsigned 32-bit shifts/xors in order x^=x<<13; x^=x>>17; x^=x<<5; wrap modulo 2^32. Initial zero maps to 0x6d2b79f5. Seed 1 first outputs: 270369,67634689,2647435461,307599695,2398689233. Draw bounded n using rejection: threshold=(2^32 mod n); draw x until x>=threshold, return x mod n. Seven-bag starts [I,J,L,O,S,T,Z]; Fisher-Yates i=6..1, swap i with bounded(i+1), consume index 0..6. Seed 1 first bag [S,I,L,O,T,Z,J]. Generate lazily when empty; include current bag, cursor and RNG in snapshots. Garbage and targeting use separate xorshift states initialized from seed XOR 0xa5a5a5a5 and seed XOR 0x3c6ef372 respectively, applying zero mapping to each. RNG changes only on actual random draw. Classic will have its own measured generator.

Future rules content identity: SHA-256 over UTF-8 canonical JSON: ASCII property names sorted lexicographically recursively, no whitespace/BOM, integers in minimal decimal, strings escaped with JSON rules, arrays preserve order, no floats/null/duplicate keys. Include all fields and table IDs. A table ID resolves to immutable normative content in its versioned specification; changing a table requires a new ID/version. This rules digest differs from M0 diagnostic FNV state hash.

# Offline Classic, Fusion and Modern SDL client

`stackpulse_client` provides local Classic/Fusion/Modern Marathon, Practice Lab, keyboard/gamepad settings, and deterministic record/replay. This is an independently authored **Classic-inspired approximation**, not a reference-validated reproduction. The SDL-free mechanics and replay verifier use the same simulation as the client.

Build with `cmake --build --preset windows-debug`. Run `out/build/windows-debug/Debug/stackpulse_client.exe` from this repository. The 640x360 logical canvas scales continuously to the largest viewport that fits the window, including when maximized. Letterboxing preserves its proportions on other aspect ratios. SDL bitmap debug text and original primitive artwork need no external font or asset files.

All seven pieces have distinct colors within each retro palette. Palette selection follows actual gravity-speed changes, including speed plateaus; locked blocks, active pieces, previews and hold use the same palette. These colors are independently authored and need no ROM assets.

## Controls

- Menus: Up/Down or W/S and Enter; controller D-pad and South. Escape or controller Back always backs out, cancels a remap, or toggles pause.
- Gameplay defaults: Left/Right move, Down soft drops, X rotates clockwise, Z counterclockwise, Escape pauses. Controller D-pad moves, South rotates clockwise, West counterclockwise, Start pauses.
- F1 pauses; F2 restarts the current seed; F3 starts the next seed; F6 saves the current replay.
- Practice: F4 advances exactly one simulation tick and pauses; F5 loads an authored four-line clear fixture. Hold Down to clear it. The pause menu also exposes frame step and the fixture.
- Settings: select a keyboard/controller action and press its replacement; conflicting and reserved shortcuts are rejected. Escape/Back cancels capture. On the start-level row, Left/Right or controller D-pad Left/Right decreases/increases the level within 0â€“29. Enter/controller South also cycles through the levels. Left stick is optional, off by default, with 0.55 engagement / 0.35 release hysteresis.

Classic has no hold, hard drop, ghost or kicks. Fusion and Modern add project-90-v1 kicks and full spin/reward rules; both enable hold; only Modern enables hard drop and a ghost. Online Fusion/Modern duels use the dedicated ENet server described below. Repeated OS keydown events do not retrigger rotation or menus. Rotation uses sampled press edges; taps completed entirely between simulation boundaries are visible in the practice timeline but do not create an extra simulation action.

Classic T, J and L pieces spawn and preview flipped 180 degrees from their original provisional orientation. Fusion pieces spawn with their top occupied cell at visible row zero (computed from each shape), with T/J/L flipped to match Classic in active, next and hold slots. Successful horizontal shifts (including DAS), soft-drop cells and rotations play short, distinct original synthesized effects. One-to-three-line clears play a rising sweep; four-line clears play a longer four-note ascending cue. Hard drop has a separate impact cue, and T-spin single/double/triple have distinct bass impacts, noise cracks and metallic tails with escalating layers and duration at bounded gain. An accepted first hold plays a descending storage cue; swapping an occupied hold plays a distinct rising retrieval cue. Rejected holds are silent. Automatic gravity and blocked attempts stay silent; playback uses the same simulation events. Launch with `--mute` to disable audio for the session. Audio-device failure leaves gameplay available.

## Persistence and replay

The SDL preference directory for `Stackpulse/Classic-v1` holds `settings.txt`, Classic `last.spcr` and Fusion/Modern `last.spmr`; the console prints its resolved path. `--data-dir PATH` overrides it. Keyboard/controller bindings, stick preference, and starting level persist. Settings format v3 accepts existing v1/v2 settings and preserves the six old bindings, assigning nonconflicting defaults to added actions. Missing or malformed settings fall back to defaults.

Every run records its complete initial state and one held-input mask per executed simulation tick. F6, pause, restart, main-menu return, and exit save the latest recording. Replay encoding/writing runs on a serialized background worker with an owned snapshot; a busy save may ask you to retry replacement/load actions. Failed snapshots remain available for retry. Replay loading still verifies synchronously. Failed saves appear in the status bar and console; reset/menu/replay-load operations stop before discarding unsaved inputs. Closing the app still exits after reporting any final save error. The 1,000,000-frame recording limit pauses the run and saves it. Only the latest recording per replay format is retained; copy it elsewhere to keep older runs.

Select the desired MODE first (Classic loads last.spcr; Fusion/Modern load last.spmr), then choose **Play Last Replay** to validate the format, rule identity, CRC, checkpoints and final hash before playback. Practice fixtures restore their full initial board and timers. Playback ignores gameplay input, supports pause and restart from the recorded initial state, and reports completion with a final hash. It does not overwrite the recording. The seed HUD says RECORDED because the original user-facing seed is not stored separately from the full RNG state.

The corrected transitions, two-state I/S/Z geometry and charged DAS use provisional rules/state version 3. Older recordings reject as incompatible; new recordings retain the SPCR v1 container and `.spcr` suffix.

`stackpulse_client --verify FILE` verifies and exits without initializing SDL, printing frames, final tick and hash; rejected files return status 1. `stackpulse_replay_verify FILE` is the standalone Classic verifier; `stackpulse_modern_replay_verify FILE` verifies Fusion/Modern SPMR.

## Timing and validation

The client samples timestamped physical transitions on rational 60 Hz boundaries. It runs at most eight overdue simulation ticks per rendered frame and retains all remaining backlog; no active simulation tick is skipped. Time spent in menus or paused is excluded from the wallclock schedule. The status bar reports overload while behind. Late SDL events move to the next unsampled boundary and are counted in the console. Focus loss pauses and releases all bindings; controller removal releases that device and pauses. Resume requires a fresh physical press for held controls.

`stackpulse_client --smoke-frames 8` bounds startup/rendering. Add `--smoke-play` for automated fixture soft drop. Bounded smoke runs do not write replay or settings files. `--sticks` enables the optional stick mapping for that process. Automated checks cannot establish physical input latency, controller compatibility, reference fidelity, or monitor-rate behavior; those still require hands-on measurements.

The prior M0 input-only shell remains available as `stackpulse_diagnostic` and has its own overload policy. Its behavior is not the playable client's simulation policy.

## Fusion/Modern additions

The home MODE row cycles Classic, Fusion and Modern with Enter/controller confirm. `--mode classic|fusion|modern` sets startup selection. Fusion shows five previews and one hold slot, disables hard drop, and uses Classic wall-charged 16/6 DAS/repeat (blocked attempts saturate at 16, retry next tick, and successful repeats reset to 10). It uses Classic uniform RNG, gravity, start-level settings and level transitions. Every piece locks on the first blocked downward attempt unless one actual CW/CCW rotation of the current T can reach a grounded three-corner spin pose using its first successful legal kick. Current completed-spin geometry and prior rotation history do not grant extra lock time; rotation history still determines spin scoring at lock. Only that local spin possibility gets a 30-tick delay and fifteen resets; leaving the cavity removes the exception. Modern shows five previews, a ghost and hold slot, 10/3 handling and 30-tick locking with fifteen resets. Default hold is C/controller left shoulder, hard drop Space/controller right shoulder; Settings contains separate keyboard/gamepad rows for both. Fusion uses Classic normal clear scoring plus escalating spin bonuses; both modes award all-clear points. See [spin candidate resolution](../../docs/issues/spin-candidate-resolution.md) and [issue-4 resolution](../../docs/issues/issue-4-resolution.md) for exact defaults. SPMR v5 rejects incompatible v1/v2/v3/v4 Modern/Fusion recordings; Classic SPCR remains unchanged.

In Fusion/Modern Practice, F7/F8/F9 select authored spin single/double/triple cavities. Press clockwise once and wait to lock (Modern can hard drop after rotation; Fusion locks on the next blocked downward attempt when the rotation leaves no further qualifying route). F10 restarts with pending garbage in the initial state; it becomes eligible after60 ticks in this authored demonstration and inserts at the following spawn boundary. Fixture/restart commands save prior recording before replacing it. The HUD shows clear/spin attack, canceled/inserted rows, pending garbage, combo and B2B.

`--smoke-play` uses a spin single in Fusion/Modern and injects clockwise on the first simulation tick; Classic retains its four-line soft-drop fixture. `--capture FILE.bmp --smoke-frames N` exports the actual renderer final frame. `--smoke-settings` selects Settings for screenshot inspection. Captures are diagnostic, without physical input/latency validation.

In Fusion/Modern Practice, F11 opens a frozen spin inspector on the current board. F12 cycles the candidate T orientation (0–3). Candidate eligibility is independent of rotation history. F11 or Escape closes it and restores the prior play/pause state. Colored cell outlines show all legal candidate poses accepted by the same core predicate used for Fusion locking: cyan CW route, pink CCW route, white both routes. A current completed spin alone is not an accepted candidate. Small squares mark local origins and crosses mark pivots. Solid cells are board blockers; live active/ghost fill is hidden. The separate ACTUAL CANDIDATE readout reports the live piece's route eligibility. SCORING READY separately reports its current grounded three-corner geometry with actual rotation history; spin scoring still requires a lock. HIDDEN counts wholly invisible accepted poses above the visible field; partly visible poses are drawn. This is a local geometry diagnostic, without a path search from spawn. Input and audio are suspended while inspecting; no simulation ticks or replay frames are added. F10 retains its garbage demo.

`--spin-debug --mode fusion --smoke-frames 5 --capture out/spin-debug.bmp` opens the inspector directly on an authored single-spin board at tick zero for renderer inspection (defaults to Fusion if no non-Classic mode is chosen).


## Online rooms (M4)

Start the dedicated server, then choose **Multiplayer / Rooms** on the home menu. The server is a separate process; localhost and port 27877 are the defaults. Select Fusion or Modern before opening Multiplayer (Classic selects Fusion). Rooms support 2–8 players plus spectators, with a named roster, connection/readiness labels and an explicit manager marker.

The connection menu supports D-pad Up/Down to select rows, South to confirm, and East/Back to cancel. Keyboard Up/Down, Enter and Escape do the same. Join Room and Watch Room use the shared default room when the room code is empty, so basic localhost play and spectating require no keyboard. Create Private Room asks the server for a new room and displays its assigned code in the lobby. Left/Right toggles player/spectator, chooses localhost or the most recently used address, adjusts the port, or clears the room code. Keyboard Enter on an address, port, room-code or name field starts text editing; Backspace erases and Enter finishes. Names default to a generated Player number; labels also identify players without relying on piece colors. The last address is saved separately in `online-host.txt`.

Enter/controller South toggles ready in the lobby. At least two players are needed, and every player must be connected and ready to begin the countdown. The lobby shows up to eight players, readiness and manager status, plus spectator count. A manager can press Enter/South after a server-confirmed result to return the room to its lobby for a new round without restarting the process. New round/room epochs clear prediction, held inputs, timing and audio deduplication. Spectators may join a playing room; they use server-confirmed boards throughout, never run local prediction and never upload gameplay inputs.

Saved gameplay bindings and optional stick settings apply online. Escape/Start toggles an input-release overlay while the match continues. Focus loss or device removal releases inputs. F9 reconnects using the private session credential; F10/controller Back leaves the session. The Escape/Start overlay also exposes Resume, Reconnect and Leave with Up/Down and Enter/South, so recovery is available from a controller. Tab/controller right-stick click cycles your attack target, or the featured player while spectating. These shortcuts are reserved in Settings; target remapping is a later extension. The main board is local prediction for a player and the featured authoritative board for a spectator. Every other participant is visible in a compact grid of up to seven boards. Spectators can cycle the featured board for a larger view.

```powershell
./out/build/windows-debug/Debug/stackpulse_server.exe --mode modern
./out/build/windows-debug/Debug/stackpulse_client.exe --connect 127.0.0.1 --mode modern --name Alice
./out/build/windows-debug/Debug/stackpulse_client.exe --connect 127.0.0.1 --mode modern --name Bob
./out/build/windows-debug/Debug/stackpulse_client.exe --connect 127.0.0.1 --mode modern --spectate
```

`--port N`, `--room CODE`, `--name NAME`, `--create` and `--spectate` also configure direct connections. Omit `--room` for the default room. `--create` creates a private room; read its assigned code from the lobby and use it with `--room CODE` on other clients. Match results and opponent boards always come from the server. Complete snapshots reconcile only the local board with stable buffered inputs. Newly sampled movement/rotation/drop/hold cues are deduplicated; reconciliation is silent. Clear/result effects remain withheld because authoritative event cues are not yet exposed by the network facade.

Online replay saving is disabled: offline local-input SPMR cannot reproduce authoritative external attacks. Existing offline practice, recordings, sound and settings remain available.

For native-process verification, `--online-bot --online-exit-ticks 2400 --mute` auto-readies and supplies inputs through the same API. Modern bots hard-drop frequently. The process succeeds only after a reliable server result and complete terminal snapshot, printing `AUTHORITATIVE_RESULT tick=... result=... hash=...`. The tick limit or a 90-second timeout without a result fails. Add `--spectate` for a bot that observes without inputs/readiness. `--capture FILE.bmp` exports the final online renderer frame. These checks do not measure physical controller compatibility or human input latency.

`--online-capture-tick N --capture FILE.bmp` captures the first playing frame at or after server tick N once, then continues the session with the normal result/timeout exit policy. It works for both players and spectators. `--smoke-multiplayer-menu --smoke-frames 8 --capture FILE.bmp --mute` renders and captures the connection menu without connecting or changing saved preferences.

`--online-ready-delay-ms N` optionally delays bot readiness from process connection startup, allowing a full native-process roster to join before countdown. The default remains immediate readiness.
